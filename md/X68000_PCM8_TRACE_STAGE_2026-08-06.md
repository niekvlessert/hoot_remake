# X68000 PCM8 trace stage — 2026-08-06

> Superseded by `X68000_PCM8_DIRECT_MIXER_STAGE_2026-08-06.md`. This file records the preceding command-only stage.

## Status

The stable X68000 YM2151, standard ADPCM, MFP, IOCS and FLOAT2 baseline remains intact. This stage adds the command-first PCM8 foundation requested by the clean-context handover. It does **not** yet render PCM8 audio.

## Implemented

- Added `X68kPcm8Mixer` as a stateful trap-#2 command endpoint.
- Decodes the original PCM8 channel functions (`$000x` through `$00Cx`) and the wider PCM8A forms (`$10xx` through `$1Cxx`).
- Decodes the documented frequency/data-format byte for:
  - X68000 ADPCM at 3.9, 5.2, 7.8, 10.4, 15.6, 20.8 and 31.2 kHz;
  - signed 16-bit PCM at the same rates;
  - signed 8-bit PCM at the same rates.
- Maintains eight independent voice states with address, byte length, remaining length, mode, pause and active flags.
- Implements normal output/start/stop, mode changes, length/mode/address queries, channel pause/resume and global stop/pause/resume/enable/disable calls.
- Returns PCM8-compatible success/failure/query values in D0.
- Recognizes array-chain and linked-array-chain calls but reports them as unimplemented instead of silently accepting them.
- Counts unknown functions and channel numbers above seven separately.
- Hooks the real Hoot PCM8 host marker `$22` for catalogue entries with `pcm8=1`; `$02` remains accepted for early synthetic fixtures.
- Adds detailed PCM8 events to `HOOT_X68K_TRACE`.
- Adds a structured `diagnostics.pcm8` object to `hootprobe` JSON.
- Adds `tools/run_x68k_pcm8_trace.py` for the Asuka 120%, Mad Stalker and Princess Maker trace gate.

## Validation

- CMake release build: pass.
- `driver_registry`: pass.
- `x68k_memory`: pass.
- New `x68k_pcm8_mixer`: pass.
- Plain OPM regression matrix: pass, 191 audio/control commands, zero warnings, zero clipping, zero unsupported CPU opcodes.

## Deliberate limitations

- No PCM8 samples are mixed into the output yet.
- Array-chain and linked-array-chain playback are not implemented.
- The first mixer target is eight voices; wider PCM8A channel use is diagnosed.
- Voice `remaining` does not advance until the audio renderer exists.
- Real-pack traces are still required to confirm which mode codes, chain forms and channel counts the target catalogue entries actually use.

## Required next input

Provide at least one of these original Hoot packs:

- `asuka68snd.zip`
- `madstk68snd.zip`
- `pm68snd.zip`

Preferably provide all three. Run:

```sh
python3 tools/run_x68k_pcm8_trace.py --packs packs --output reports/x68k-pcm8-trace.json
```

The resulting command inventory determines whether the next audio step can start with direct ADPCM blocks only or must include chain tables immediately.
