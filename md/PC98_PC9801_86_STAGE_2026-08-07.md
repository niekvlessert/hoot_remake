# PC-98 PC-9801-86 Stage — 2026-08-07

## Scope

This stage extends the generic PC-98 DOS/V30 replay host from OPN/OPNA to
`pc98dos/86`.  The YM2608 remains the FM/SSG/rhythm device; the PC-9801-86
linear PCM path is modeled as a separate board-level FIFO/DAC rather than as
YM2608 Delta-T audio.

## Implemented PC-9801-86 PCM interface

The new `Pc98Pcm86` component implements the guest-visible A460h-A46Ch interface:

- A460h sound-ID / extended-FM latch
- A466h PCM volume and FIFO empty/full/phase status
- A468h FIFO control, reset, sample-rate selection, low-water IRQ state and playback enable
- A46Ah DAC mode or programmable FIFO low-water threshold
- A46Ch FIFO sample writes
- 32 KiB logical FIFO behavior with deterministic overrun handling
- all eight rate selectors: 44100, 33075, 22050, 16537.5, 11025, 8268.75, 5501.25 and 4134.375 Hz
- signed big-endian 16-bit mono-left, mono-right and stereo modes
- signed 8-bit mono-left, mono-right and stereo modes
- low-water interrupt scheduling and acknowledgement
- independent PCM86 mixing after YM2608 output
- Hoot `pcm_mix` scaling for the 86PCM path

The implementation follows the PC-9801-86 behavior documented by the Neko
Project/DOSBox-X `pcm86io.c`, `pcm86c.c` and `pcm86g.c` implementations.  The
host deliberately keeps PCM86 separate from the YM2608 ADPCM-B memory already
used by ordinary `pc98dos/opna` entries.

## Generic PC-98 integration

`pc98dos/86` is now recognized by the normal `Pc98DosDriver` and reports replay
host `pc98dos-v30-86`.  It reuses the existing generic DOS services, COM/MZ-EXE
loader, resident shell chain, file open/read/seek/close handling, Timer A/B
scheduling, BIOS sound hook and legacy INT 0Bh fallback.

PCM86 low-water interrupts enter the same resident sound-service layer.  This
keeps P86/PMD86-style streaming compatible with the existing PC-98 resident
architecture without adding game-specific callbacks.

## Diagnostics

`HootTrackInfo` and `hootprobe` now report a separate `pcm86` block containing:

- port writes
- FIFO writes / reads
- rendered host and source frames
- IRQ requests / deliveries
- FIFO overflows
- current and peak FIFO occupancy
- FIFO threshold/control
- DAC mode
- PCM volume code
- selected source rate

This makes a real 86-pack validation able to distinguish true 86PCM activity
from a track that happens to use only the YM2608 on the same board.

## Tests

Release build:

- 9/9 CTest targets pass.
- `pc98_pcm86_test` validates all eight sample-rate selectors and all six valid
  signed PCM channel/width modes, 16-bit byte order, stereo polarity and
  low-water IRQ behavior.
- `pc98dos_generic_driver_test` now also validates `pc98dos/86` registry and
  YM2608 operation.
- A separate synthetic PC-98 DOS shell writes 4096 PCM bytes through A46Ch and
  must produce audible PCM86 output with >4000 FIFO writes/reads and no CPU
  opcode failures or FIFO overruns.

ASan + UBSan:

- 9/9 CTest targets pass.
- PCM86 and the integrated DOS/86 synthetic path pass with sanitizer halt-on-error enabled.
- Representative real Ys PC-88 and Slayers PC-98 tracks also pass under the sanitizer build.

## Existing real-pack regression

The six previously supplied real archives were re-run across all catalog
tracks after this change.  Result: 438 tracks total, 436 audio-active, one
intentional `[STOP]` entry and the already-known `nekoex-98-opn` `QUIZ002.FN1`
PMD 4.0b/data incompatibility.  All 69 NekoEX OPNA tracks remain audio-active.
No new PC-88/PC-98 regression was introduced.

## Catalog coverage

Current catalog counts for `pc98dos/86`:

- 162 configurations
- 162 unique archives
- 6678 catalog tracks
- 156 configurations fit the generic DOS + YM2608 + PCM86 model without another declared feature
- 6 configurations request `extramsize=0x400000` and remain explicitly deferred
  pending EMS/extra-memory sample-storage validation

Across `pc98dos/opn`, `pc98dos/opna` and `pc98dos/86`, the catalog contains 2008
configurations / 56150 tracks.  The current structural matrix classifies 1775
configurations as generic-core candidates and 233 as requiring a deferred
feature (primarily PC-98 MIDI, wstimer/dummy sound-ROM behavior, or the six
86/EMS cases).

## Evidence boundary / remaining work

No real `pc98dos/86` music archive was present in this session.  Therefore this
stage establishes hardware/API correctness, integration, diagnostics and
non-regression, but does **not** yet claim broad real-pack PC-9801-86 audio
compatibility.

The next validation should include at least one ordinary PMD86/P86DRV pack and
one EMS-backed pack, for example:

- `outsider_98.zip` or `imd_4_98.zip` — ordinary PMD86/P86DRV path
- `fc98v12.zip` or `imd_1_98.zip` — `extramsize=0x400000` / EMMDRV path

A real pack may expose CPU-time/FIFO-polling details or a different IRQ service
pattern; those should be fixed generically rather than with per-game workarounds.
