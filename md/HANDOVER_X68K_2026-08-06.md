## A-Train II fix

A-Train was blocked during A2.X initialization. Its bootstrap calls routines
with `A6=0`; local accesses such as `-8(A6)` and `-4(A6)` wrap to `0xfffff8`
and `0xfffffc` in the 24-bit address space.

Original Hoot initializes every unmapped 64 KiB bank against one writable dummy
page. The port previously returned zero and discarded writes in the top bank,
so the A2.X initialization loops never converged. The driver now preserves a
writable `0xff0000-0xffffff` compatibility page.

The bootstrap also enables MFP sources before installing handlers for all of
them. When a pending source still targets the standard `NOP / BRA.S -4` sink,
the port masks only that source and completes the already accepted interrupt
through an RTE trampoline in the compatibility page. Installed OPM/MFP vectors
continue normally.

No A-Train-specific branch or hardcoded music address is used.

## Other implemented X68000 behavior

- writable packed-data memory through `0xe7ffff`;
- Human68k `.X` image loading and relocation;
- FLOAT2 line-F dispatch needed by the tested pack;
- IOCS `_OPMINTST`, `_B_INTVCS`, `_B_LPEEK`, OPM and ADPCM calls;
- YM2151 timer interrupts and MFP routing;
- OKIM6258/ADPCM playback path;
- Hoot-compatible `opm_mix`, `pcm_mix`, and `total_mix` scaling;
- signed-16 and float rendering;
- delayed-start and control-command handling in `hootprobe`;
- centralized capability registry and isolated batch probing.

## Build and tests

```sh
cmake -S . -B build
cmake --build build -j2
ctest --test-dir build --output-on-failure
```

Both unit tests currently pass.

Run the supplied-pack gates with:

```sh
./tools/run_x68k_pack_smoke.py --packs packs
./tools/run_x68k_mfp_smoke.py --packs packs
```

Copyrighted packs are not included in release ZIP files.

## Evidence boundary

The matrices establish successful initialization, track selection, active audio,
chip writes, key-ons, and basic signal health. They do not prove sample-exact
pitch, tempo, envelopes, loop points, balance, or ADPCM fidelity.

## Recommended next work

1. Obtain trusted original-Hoot WAVs for a small representative set and add
   deterministic audio-fingerprint/regression comparisons.
2. Inventory and implement PCM8 packs as a separate capability family.
3. Add a MIDI synthesizer backend only after deciding whether MT-32 emulation,
   Sound Canvas/GM rendering, or external MIDI output is the preferred target.
4. Expand the X68000 pack matrix before changing `experimental` families to
   `verified`.

No additional pack is required to preserve the current OPM/MFP/FLOAT2 work.
The most useful next input is original-Hoot reference audio for matching tracks.
